### **Description**

To streamline the device request process for high-priority personnel, the Slack approval workflow will be bypassed for users identified as Executives or Executive Assistants. Instead, once a request is submitted, a work order will be created directly in Remedy without requiring manager approval through Slack.

---

### **Acceptance Criteria**

1. If the requester is an Executive or Executive Assistant, the Slack approval workflow is skipped.
2. A Remedy work order is created automatically after the request submission.
3. Non-executive users continue to follow the existing Slack approval workflow.
4. User role identification is based on a predefined list or directory group.
5. Proper logging is maintained indicating the workflow path taken (skipped or standard).

### **User Story Title:**

Initial Titan API Onboarding – Token Authorization and Team Registration

### **Description:**

Begin the Titan onboarding process by authorizing the API token, reviewing general API capabilities, and registering the application team and its corresponding AD group using the Titan API. This foundational setup enables the application to securely interact with Titan for telemetry onboarding.

### **Acceptance Criteria:**

1. Successfully authorize the API token using Titan's authentication flow.
2. Review and validate general API calls for usability and connectivity.
3. Register the application’s team and associated AD group using the `/api/teams` endpoint.
4. Confirm team and AD group registration is reflected in Titan’s Swagger UI or dashboard.
5. Errors or exceptions during token authorization or team registration are logged and handled appropriately.
