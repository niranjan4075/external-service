---

### Description

Build and maintain an automated asset data pipeline that pulls device and user information from multiple sources (Power BI reports, CrowdStrike, Intune, etc.) into a single Storefront inventory table. The pipeline should normalize and merge these feeds to create a consistent view of user-to-device mappings, EOL status, and group tags that can be consumed by Storefront workflows and reporting.

---

### Acceptance Criteria

* Data ingestion is set up from all required sources (Power BI report, CrowdStrike, Intune and any future-approved feeds).
* Mappings are defined so user identifiers, device IDs, platform details, EOL dates, and group tags are normalized into the inventory table schema.
* Merge and de-duplication logic ensures each active device/user record appears once with the most recent attributes.
* Pipeline runs on a defined schedule with logging, basic error handling, and monitoring to detect failed or partial loads.
* Validation checks (sample comparisons and record counts) confirm that inventory data matches source systems within agreed tolerances.

---

### Benefit Explanation

This feature creates a single, trusted source of asset data for Storefront by automatically consolidating information from Power BI, CrowdStrike, Intune, and other systems. It reduces manual reconciliation, improves accuracy of user and device records (including EOL and group tags), and enables more reliable automation, analytics, and decision-making across Mobility Operations.
